AI agents fix bugs in your team chat. Nothing merges unless a person approved that exact commit.

Loopback is a merge gate that lives in Switch rooms. Someone reports a bug in chat, one AI agent fixes it, a second checks the fix, and a maintainer approves one exact commit. If the code changes after that, the approval stops counting and the merge is refused.

Run a bug through it See it stop without Switch Jump to the late commit

The run takes about five minutes and needs no install. You type the same messages a real team types, and see the gate's real answers. The evidence console is the real app, and the other screens are close copies, labelled as such.

The problem it solves

What goes wrong todayWhat Loopback does
A maintainer says "looks good", then one more commit lands before the merge.An approval names one full commit. The gate re-reads GitHub before merging, and any new commit voids the evidence.
An agent says its tests passed when they never ran.The gate trusts GitHub's CI results and a signed report tied to one run and one commit. An agent's word counts for nothing.
A public bug report carries instructions aimed at the agent.No agent sees a report until a maintainer accepts it, and the report reaches the agent fenced as untrusted data.

How one bug moves through it

  1. 1ReportAnyone, in the public room
  2. 2AcceptA maintainer decides it's worth fixing
  3. 3FixThe fixer agent opens a pull request
  4. 4VerifyCI runs, and the verifier agent signs a report for that commit
  5. 5ApproveA maintainer names the full commit
  6. 6MergeThe gate re-reads GitHub, then merges that commit

If a new commit lands at any point after step 3, the case goes back to step 4. CI, the verifier and the approval all have to be earned again.

Who does what

SwitchRuns the rooms, connects people and agents, and tells the gate exactly who sent each message.
The gateA custom Switch agent. It holds the rules and is the only thing allowed to merge.
MaintainersPeople on an exact list of Switch ids. They accept, approve and merge, in chat.
Fixer agentReproduces the bug with a failing test, fixes it and opens a pull request.
Verifier agentChecks the fix independently and signs its report for one commit.
GitHubThe source of truth for code. Its rules refuse any merge without the gate's own status.

    How it's built

    A Node 22 and TypeScript service connects to Switch as an agent, keeps its state and audit log in SQLite, and is the only identity allowed to merge on GitHub.

    Not proven yet

    • On the live run a person guided the verifier step by step. It hasn't yet completed its brief alone.
    • The agents ran on the host, not in their isolated containers, so verification is labelled advisory in chat. A signature proves a report wasn't altered, not that its tests ran. A person should review the diff before approving.
    • A commit landing after approval hasn't been seen live, nor have why, board, team and the room documents. The rehearsal and tests cover them, against stand-ins for Switch.
    • Nobody else has done the live setup from a clean clone, and the template hasn't been run end to end.
