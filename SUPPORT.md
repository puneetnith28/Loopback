# Getting Support with Loopback

Thank you for using Loopback. Here is how to find help, report issues, and participate in discussions.

## Documentation

Before filing an issue or asking for support, check our technical documentation:

- [README.md](README.md) — System overview, quickstart, and core capabilities
- [docs/architecture.md](docs/architecture.md) — System architecture and component interactions
- [docs/threat-model.md](docs/threat-model.md) — Security model, invariants, and residual risks
- [docs/setup.md](docs/setup.md) — Setup and credential configuration
- [docs/operations.md](docs/operations.md) — Gate configuration and runtime flags
- [docs/windows.md](docs/windows.md) — Windows native runtime notes and platform limits
- [CONTRIBUTING.md](CONTRIBUTING.md) — Developer guidelines and testing procedures

## Reporting Bugs

If you find a bug in Loopback:

1. Search existing [GitHub Issues](https://github.com/puneetnith28/Loopback/issues) to verify it has not already been reported.
2. If it is new, open an issue using the Bug Report template.
3. Include your operating system, Node.js version, configuration flags (redacting all keys and secrets), reproduction steps, and relevant log outputs.

## Feature Requests

Feature proposals and architectural enhancements should be opened as GitHub Issues using the Feature Request template. Please explain:
- The problem you are trying to solve.
- Why existing mechanisms are insufficient.
- Proposed solution and how it impacts the gate's security invariants.

## Security Vulnerabilities

**Do not file public GitHub issues for security vulnerabilities.**

Please follow our [Security Policy](SECURITY.md) to report vulnerabilities privately via GitHub's Private Vulnerability Reporting on this repository.
